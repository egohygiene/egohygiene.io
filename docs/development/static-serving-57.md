# Local Docker and static serving — issue #57

## Checkpoint A: contract and audit

Alan selected #57 on 2026-10-26, with actual local testing to be walked through
on his Mac afterward. Input is draft #108 at
`4faaebeb50b4202e8aaf9ee0012db0f836939f79`; live main remains
`89fc70440f9c3cf32d37a6da83c7a2b969efa97d`. Earlier drafts #105–#108 are
unmerged. This work stacks on #108; it selects no license and activates nothing.

The original Dockerfile sends the entire checkout with `COPY . .`, has no ignore
file, uses a floating Node patch tag, and installs with lifecycle scripts disabled.
Its final image contains only normal website output and the Caddyfile. No current
secret exposure in a served image is asserted. Original Caddy serves the homepage
for missing paths and does not implement the no-trailing-slash canonical policy.
ADR 0012 already establishes generated route HTML and a separate missing page;
this issue implements its intended-server boundary without changing the renderer.

Docker and Caddy executables are unavailable in this environment. Source checks,
verifier regression tests and source-completeness builds can run here; actual
Docker ignore semantics, locked container installation, image build, Caddy syntax
and live Caddy HTTP behavior require the prepared local command on the Mac.

## Implementation boundary

- Default-deny Docker context: exact root build configuration, workspace manifests,
  website source/public files, required package source and build adapters. Exclude
  local environment/auth files, keys, dependencies, Git internals, caches, generated
  outputs, raw artwork, records and unrelated docs/archive/test applications.
- Keep Node 24.21.0 and pnpm 11.28.5 aligned with existing tooling. Retain frozen
  installation and disabled lifecycle scripts. Build only the normal public
  artifact; no isolated preview or provider credentials are accepted.
- Keep Caddy and static files as the runtime; no request-time React server, cloud
  adapter or new framework. Use emitted file existence rather than a second route
  catalog. Serve known clean paths with their matching generated bytes.
- GET/HEAD health succeeds; known trailing-slash and index.html aliases redirect
  permanently to canonical paths while preserving query bytes. Missing routes
  receive the generated noindex document with HTTP 404. Missing asset requests
  receive a non-HTML 404. Unsupported methods receive 405. Directory listing stays
  disabled. Actual hosting, TLS/DNS and production-origin verification remain #89.
- Extend the existing qualifier and Taskfile with an explicit static-server profile.
  Build a fresh image, extract its exact served artifact, check existing raw HTML
  invariants, then verify loopback-only HTTP status/MIME/bytes/aliases/health.
  Capture source, image/config/artifact identity and individual results; always
  remove the invocation-owned container. Do not reuse an unrelated local server.
- Preserve existing #52/#29 output investigations, strict size findings, native
  Storybook/browser gaps and hosted failures. This serving profile is separate
  evidence, not a substitute for complete qualification.

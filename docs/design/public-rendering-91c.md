## A real preview regression found and fixed

The first HTTP check found `/about` returning the homepage's bytes even though
`about/index.html` was correctly generated. The existing Vite 8.2 preview fallback
recognizes directory paths ending in `/`, but clean `/about` fell through to the
SPA homepage. Client rendering could hide this from a JavaScript-enabled visit.
[The reproduction](reviews/public-rendering-91c/preview-regression.json) retains
the different observed/expected hashes.

`scripts/vite-public-pages.mts` uses Vite's supported `configurePreviewServer`
hook to map exact generated GET/HEAD paths to their files before static serving.
It reads the completed `public-routes.json`, validates unique/safe paths, expected
file mappings, hashes and matching root markers, and requires the homepage.
Missing/malformed/stale normal artifacts fail startup with a rebuild instruction.
It changes the internal file lookup, preserving the browser URL and query bytes.

Dev serving has no new hook; explicitly isolated `dist-preview` remains a SPA.
Unknown routes, assets and trailing-slash handling keep Vite's existing behavior.
This is a local preview adapter, not a production hosting configuration. Sources:
[Vite hook documentation](https://vite.dev/guide/api-plugin#configurepreviewserver)
and the installed 8.2.0 preview/static/fallback implementation. No external code
or dependency was copied or upgraded.

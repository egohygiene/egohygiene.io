## Mechanical creation sequence, once selected

1. Approve one public-safe brief: physical item/design, title/story, allowed
   derivatives/alt text, optional associations, credits and desired placement.
   Public display approval is separate from production/sale approval.
2. Preserve existing IDs/slugs. For a new design, use the existing
   `node scripts/store-catalog.mts add-design --slug "approved-slug" --title "Approved public title"`.
   That example writes a draft; run it only after replacing the reviewed values.
   Follow the [existing authoring templates](catalog-authoring.md) for the product
   and optional context/collection; do not copy this example into production blindly.
3. Apply the selected public copy/artwork using the [content workflow](storefront-content-workflow.md).
   Validate design/product references and curation together. Start physical items
   in `purchase.state: "preview"`; no price/route is needed for a preview.
4. Run `pnpm catalog:validate`, `pnpm catalog:test`, `pnpm typecheck` and a fresh
   normal `pnpm build`. Inspect the actual staged files and emitted projection;
   draft flags do not make a public Git commit private. Reuse existing raw-route,
   browser/gallery and artwork-failure checks on the selected draft.
5. Review the actual rendered design/product/collection/artist views with Alan.
   Save exact public-safe IDs/revision and the remaining private worksheet inputs.
6. If Alan later selects a provider-account draft action, first verify its real
   privacy/activation behavior. Retain the private worksheet if creation would
   make a listing public. Any actual account/product creation remains separately
   selected; a schema, template or provider URL cannot supply that authority.
